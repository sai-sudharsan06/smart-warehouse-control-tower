### Module 1: Product Master Data (2026-11-19)
- `products` table with database constraints: unique name (case-insensitive),
  cost and lead time not negative, required fields
- System-assigned product IDs, displayed as `MAT-00001`
- Input validation in Python (`validate_product`) shared by create and edit
- Register, list, search (ID, name, category, supplier) and edit products
- Text cleaning: leading, trailing and repeated spaces are removed
- Field-level change history (`product_changes` table): field, old value,
  new value, user, timestamp, written in the same transaction as the change
- Foreign key from `product_changes` to `products`, enforced
- Automated tests: 32 (7 validation, 25 database), run against a temporary
  database so real data is never touched

Module 1 close-out: process diagram (Draw.io) and screenshots in `docs/`.

### Module 2: Warehouse Structure Management (2026-11-19)
- `zones` (code, name, type) and `storage_bins` (zone, rack, level, blocked flag)
- Zone types: Receiving, Storage, Picking, Shipping, Quarantine, Damaged
- Bin codes generated by the system (`A-01-02`), never typed by hand
- Single bin or a whole rack/level range in one all-or-nothing transaction
- Screen: Warehouse structure

### Module 3: Inventory Management (2026-11-19)
- `stock` (quantity per product and bin) and `stock_movements` (ledger)
- Every stock change goes through one function (`post_movement`) that writes
  the movement and the stock change in the same transaction
- Movement types: goods receipt, putaway, transfer, goods issue, count
  adjustment (+/-); each records source, destination, quantity, user, time
- Stock status follows the zone type; only Unrestricted stock (Storage and
  Picking) is available. Quarantine and Damaged stock is never available.
- Checks: no negative stock, no moving more than is in the bin, blocked bins
  refused, quantities rounded to 3 decimals
- Ledger check: rebuilds stock from the ledger and reports any difference
- Screen: Inventory (overview, move stock, movement ledger)

### Module 4: Goods Receiving (2026-11-19)
- Goods receipts (`GR-00001`) against a delivery note, booked into a

- Putaway with a suggested bin: a bin that already holds the product, else
  the first empty storage bin
- Screen: Goods receiving

## Known limitations
- **No real login.** The "current user" is typed in the sidebar and is not
  authenticated. Real systems take the user from the login.
- **Unit cost is stored as a floating-point number (REAL)** and rounded to
  2 decimals. Enterprise systems use exact decimal types for money.
- **Product creation is not in the change history** (only edits are).
  `created_at` records when, but not who.
- **Products cannot be deactivated from the screen yet.** The `is_active`
  column exists, but no screen uses it.
- **Search treats `%` and `_` as wildcards** (SQL `LIKE` behaviour).
- **After renaming a product, the edit dropdown shows the old name** until the
  next click. The database and the product table are correct immediately.
- **Timestamps are stored in UTC** and shown in UTC (one hour behind German
  winter time).
- **Changes made before the change history existed are not recorded.**
- **After pulling new code, restart Streamlit** (Ctrl+C, then
  `streamlit run app.py`). A running server can keep old code in memory.
- **Bin capacity is not modelled.** Putaway suggestions ignore size and weight.
